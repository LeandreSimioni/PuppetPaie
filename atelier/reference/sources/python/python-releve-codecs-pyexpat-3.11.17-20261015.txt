# Releve des noms d'encodage que Python 3.11.17 connait, par ce que `pyexpat` en fait.
#
# CE N'EST PAS UN TEXTE PUBLIE : c'est un RELEVE du comportement de l'interpreteur, fait le 15/10/2026 sur ce
# conteneur, par la fonction `codecs_connus` de l'ancien `atelier/outils/generer_tables_retours.py` (supprime le
# meme jour). Il fige ce que le moteur accepte aujourd'hui ; voir `LISEZ-MOI.md`, qui dit d'ou vient chaque classe.
#
# La regle (`python-cpython-3.11.17-pyexpat-20261015.txt`, `PyUnknownEncodingHandler`) : pour un nom qu'expat ne
# lit pas lui-meme (`retours::codage` les reconnait avant cette table), pyexpat decode les 256 octets avec le codec
# de Python (`replace`) et s'en sert comme table si cela rend 256 caracteres, sinon `ValueError` (multi-byte encodings are not
# supported). Un nom que Python ne connait pas : `LookupError`.
#
# Les noms : les modules de `encodings` et les cles et valeurs de `encodings.aliases.aliases`
# (`python-cpython-3.11.17-encodings-aliases-20261015.txt`), codecs de texte seulement (`_is_text_encoding`),
# normalises comme `encodings.normalize_encoding`, en minuscules. Une classe par section :
#   [latin1]  la table identite ; [ascii] l'ASCII, le reste refuse ; [cp1252] windows-1252 ;
#   [autres]  une autre table de 256 caracteres (que le moteur ne porte pas) ; [refuses] pas 256 caracteres.
